# 轨交车辆故障处置助手 Agent

轨交车辆故障处置助手 Agent 是一个面向轨交车辆运营现场的智能故障处置辅助系统。系统基于服务器端部署的大语言模型、轨交车辆故障处置知识库、RAG 检索和工具调用能力构建，能够为司机、检修人员和应急处置人员提供故障问答、处置建议、Word 文档生成和流程图生成能力。

本作品采用纯服务器部署方式：大语言模型服务、Flask 后端服务和 React 前端页面均部署在服务器环境中。用户通过浏览器访问在线 Demo，即可完成故障问答、文档生成和流程图生成等操作。

## 作品定位

在轨道交通运营场景中，车辆故障处置具有时效性强、流程要求严格、安全边界清晰等特点。传统故障处置依赖人工查阅手册、经验判断和调度指令，信息检索与流程整理耗时较长。

本作品面向“轨交车辆故障现场处置”这一具体场景，将故障处置文档、车辆系统知识、大模型推理能力和自动化工具结合起来，形成一个可运行、可演示、可交付处置材料的 Agent 应用。

系统不仅能够回答“应该怎么处理”，还能够进一步将回答加工成可下载的 Word 处置建议和手机端友好的竖版 PNG 流程图，用于现场传达、复盘记录和比赛演示。

## 核心能力

- **故障问答**：基于轨交车辆故障处置知识库回答司机和检修人员的问题。
- **知识检索**：根据用户问题检索相关故障处置切片，辅助大模型生成可靠回答。
- **流式响应**：大模型回答以流式方式展示，提升交互体验。
- **任务规划展示**：在生成产物前，系统显式展示 Agent 对任务的拆解过程。
- **工具调用展示**：系统展示 Word 生成、流程图生成、自动测试等工具调用记录。
- **Word 文档生成**：自动生成 `故障处置建议.docx`，包含文字说明、处置步骤表、设备开关信息、安全提醒和执行记录。
- **PNG 流程图生成**：自动生成 `故障处置流程图.png`，采用竖版流程图样式，适合手机查看和现场传播。
- **自动测试与改进**：系统自动检查生成文件是否可用、结构是否完整，并在必要时补充安全提醒、结束节点等内容。

## Agent 特征

本作品基于 AI 大模型构建，并具备明确的 Agent 特征，主要体现在工具调用能力和任务规划能力。

### 1. 任务规划

用户点击“生成并下载word”或“生成并下载流程图”后，系统会启动独立的产物生成 Agent 工作流。页面会展示系统对任务的规划过程：

- 读取用户问题和模型回答。
- 识别故障场景。
- 拆解处置步骤。
- 识别设备编号、开关位置和安全提醒。
- 规划 Word 文档结构或流程图节点结构。
- 准备生成最终交付文件。

### 2. 工具调用

系统在后端实现了真实的工具调用链。当前工具包括：

- `extract_disposal_plan`：从模型回答中提取结构化处置计划。
- `generate_docx`：生成 Word 处置建议文档。
- `validate_docx`：校验 Word 文件、标题、表格、步骤行数和安全提醒。
- `extract_flowchart_plan`：提取流程图节点与流程结构。
- `generate_flowchart_png`：绘制竖版 PNG 故障处置流程图。
- `validate_flowchart_png`：校验 PNG 文件、画布尺寸、节点数量和竖版布局。

### 3. 执行记录

每次生成 Word 或流程图时，前端会实时展示 Agent 执行记录，包括：

- 任务规划
- 任务执行过程
- 工具调用
- 自动测试
- 自动改进
- 最终提交成果

这些记录不是静态说明，而是由后端在实际执行过程中通过 SSE 事件推送到前端。

### 4. 自动测试与自动改进

系统生成文件后会自动执行测试。例如：

- 检查 Word / PNG 文件是否生成。
- 检查 Word 是否可打开。
- 检查 Word 是否包含标题、表格和安全提醒。
- 检查流程图是否为 PNG。
- 检查流程图是否为竖版布局。
- 检查流程节点数量是否满足要求。

如果发现内容缺失，系统会根据规则进行自动补充并重新生成。

## 部署形态

本作品采用服务器集中部署：

- 大语言模型部署在服务器端，提供 OpenAI 兼容接口。
- Flask 后端部署在服务器端，负责知识库检索、大模型调用和工具执行。
- React 前端构建后由 Flask 后端统一提供静态页面。
- 用户通过浏览器访问服务器地址，无需在本地安装模型或运行代码。

服务器部署后的访问形式为：

```text
http://服务器地址:5000
```

在正式展示环境中，也可以通过 Nginx、域名和 HTTPS 对外提供访问。

## 页面功能

- 左侧栏展示系统名称、知识库说明和历史对话。
- 主区域展示用户问题、大模型回答和操作按钮。

## 后端 API

### `GET /api/health`

返回系统健康状态、知识库文件路径和切片数量。

### `POST /api/chat`

接收用户问题，执行知识库检索并调用大模型，以 SSE 流式返回回答。

### `POST /api/artifacts/word`

根据用户问题和大模型回答生成 Word 处置建议，以 SSE 返回执行过程和最终下载链接。

### `POST /api/artifacts/flowchart`

根据用户问题和大模型回答生成 PNG 竖版流程图，以 SSE 返回执行过程、预览链接和最终下载链接。

### `GET /api/files/<filename>`

提供 Word 文档和 PNG 流程图的下载或预览能力。

## 知识库说明

系统内置地铁车辆故障处置知识库切片文件，内容来源于轨交车辆故障处置方案。知识库按故障类型、设备系统、处置流程和标签进行切片，便于后端根据用户问题进行检索。

## 生成产物

系统运行过程中会生成文本回答和两类文件：

```text
文本回答
故障处置建议-xxxx.docx
故障处置流程图-xxxx.png
```

这些文件由 Agent 工作流实时生成，并保存在服务器中。用户可通过页面按钮下载，也可在流程图生成后直接在页面中预览 PNG 图片。

## 当前版本实现方式

当前版本采用“服务器端大模型 + 固定 Agent 工作流 + 真实工具调用”的实现方式：

- 大模型负责根据知识库生成故障处置回答。
- 后端工具负责将回答转换为结构化处置计划。
- Word 工具负责生成 `.docx` 文档。
- 流程图工具负责生成 `.png` 图片。
- 自动测试工具负责检查生成结果。
- 前端负责实时展示 Agent 的规划、执行、测试、改进和成果。


## 作品亮点

- 将轨交车辆故障处置这一垂直场景与大模型能力结合。
- 支持基于知识库的可靠问答，减少纯模型幻觉风险。
- 具备可视化 Agent 执行过程。
- 具备真实工具调用，能够自动生成 Word 和 PNG 文件。
